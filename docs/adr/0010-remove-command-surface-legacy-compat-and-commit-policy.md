# ADR 0010：删除 `/fl` 命令表面、旧库兼容与本机提交时间策略

- 状态：已接受（2026-10-28，所有者要求按照最新项目文档删除冗余代码和功能）
- 依据：[统一方案 §6](../product.md#6-全新存储与一致性协议)、[§8.1](../product.md#81-客户入口与业务工作台)与[§14](../product.md#14-实施边界与待决项)
- 接续：[ADR 0009](0009-remove-retired-implementation.md)；实际范围与验证见[清理记录](../status.md#14-命令表面旧库兼容与提交策略清理2026-10-28)

## 背景

统一方案已确认：首版不提供 ForgeLoop 斜杠命令，客户入口是 DSH 业务工作台与专用会话模式；
新库从空库和新模型开始，不承担旧业务库兼容、迁移或只读历史查询。
ADR 0009 曾保留仍在运行的 `/fl` 命令与旧库补列，作为替代入口和存储方案完成前的过渡。

所有者随后明确要求删除 `/fl` 系列命令、旧库兼容和本机提交时间策略。继续保留这些代码会让
文档、契约和命令表面继续暗示新方案已支持人工批准入口，也会让旧库兼容被误读为当前存储承诺。
本机提交时间策略还附带仓库内脚本、配置模板、年历、钩子与 CI 作业，属于所有者要求删除的
本地流程约束，不再是项目交付的一部分。

## 决定

1. 删除 `packages/forgeloop/src/commands.ts` 及插件注册；`inject` 不再依赖 `ctx.commands`。
   删除命令专用测试、`contracts/cli-contract.json` 与相关契约校验。
2. 模型工具继续只读查询与受理需求，不获得批准、验收、推进或停止能力。当前客户决定入口为空缺，
   由后续实现和验证补齐；工具参数、消息角色或文档声明都不能填补。
3. 删除旧库补列逻辑与“可读旧库”的兼容声明。记录层只按当前结构建立和读写权威表；
   旧业务数据、证据和数据库文件不因本决定被清理。
4. 删除只服务于命令表面的 UI（复制命令按钮与文案）、运行提示中的 `/fl` 指令和安装检查脚本的
   命令探针；运行时业务流水线仍在，供未来可信入口和测试复用，不据此宣称已有客户入口。
5. 删除本机提交时间策略：`scripts/ts/commit-policy.ts`、配置模板与年历、`.githooks/`、
   `make` 目标、CI 作业和相关文档。提交授权只来自所有者的明确要求，提交消息仍遵循
   Conventional Commits；本机 `core.hooksPath` 与生效配置同时移除。
6. 更新架构契约、架构说明、状态记录、术语和安装说明，明确这些能力已删除且替代入口尚未实现。

## 后果与回查

- 插件当前可以受理需求并读取记录，但没有人类批准、推进、验收或恢复入口；从受理到交付的完整
  人工闭环不可用。这是新入口尚未实现期间的如实边界，不是新的授权模型已经完成。
- 旧库不再被当前实现读取或补列；旧数据库与证据保留在原地，是否清理另行决定。
- 删除的源码与契约可从 Git 历史按原路径回查，例如：

```sh
git show b344b5a08407f0f94ab5d3ca90887ecf17a24e7f:packages/forgeloop/src/commands.ts
git show b344b5a08407f0f94ab5d3ca90887ecf17a24e7f:contracts/cli-contract.json
git show b344b5a08407f0f94ab5d3ca90887ecf17a24e7f:docs/adr/0002-commit-policy-as-local-opt-in.md
```

- 统一方案中的工作台、专用会话模式、自主交付与全新存储仍需实施和真实验证；本批未提供这些能力。
