# ADR 0008：ForgeLoop 转为 TypeScript 原生 DSH 插件

- 状态：已接受（2026-10-22，所有者当日决定）
- 取代：[ADR 0006](0006-supervised-hot-upgrade.md) 与 [ADR 0007](0007-web-operations-console.md) 所描述的“独立 serve／Web 操作台作为产品宿主”路径
- 相关：[十小时目标](../dsh-plugin-10h-goal-prompt.md)、[DSH 平台采用评估](../library/research/2026-10-22-dsh-platform-adoption-assessment.md)、[DSH 宿主内持久工作](../library/research/2026-10-22-dsh-hosted-durable-workflows.md)

## 背景

2026-10-22 之前，ForgeLoop 是一个 Python 产品：`forgeloop serve` 承载 HTTP、网页、会话、
worker、邮件与热升级；需求、任务包、批准、证据与动作记录在 SQLite。Python 侧已有真实
自迭代记录（A01、G01/G02），但交互平台（网页、会话壳、工具轨迹）持续占用研发注意力，
且旧研究笔记中“保留 Python 核心／子进程桥接”的过渡建议已无法满足所有者的产品方向。

所有者当日决定：**把 ForgeLoop 全部转为 TypeScript 实现的原生 DSH 插件，以 DSH 为唯一
常驻产品宿主，不保留 Python 业务核心或跨语言桥接；首版就能在 DSH 中受理对插件自身的
改进需求，完成真实开发、独立审查、正式测试、打包和本地升级，并在新版本中验证改进。**

参考实现确认了可用接缝（本地参考源码提交 `687f282e8625c6b8d11ff58211a90524be2e4317`，
本机运行版本 `0.2.1-rc.2`）：`ctx.agents.create`＋`followup`＋`whenIdle` 可在宿主内运行
真实 Agent；`ctx.commands.register` 承担人类命令；`ctx.tools.register` 承担模型工具；
`ctx.subprocess` 管理受控子进程；SQLite 可由 Node 内置 `node:sqlite` 访问。

## 决定

1. **单一产品宿主**：DSH 是唯一需要单独启动与监督的常驻产品。用户不再启动
   `forgeloop serve`、`forgeloop-launcher`、独立 HTTP 服务或后台守护进程。
2. **单一语言**：领域规则、持久化、业务编排、插件接入、测试、数据迁移、构建辅助与
   质量／契约检查中的自有可执行逻辑统一使用 TypeScript；发布 JavaScript 由 `tsc` 生成。
   不通过 Python 子进程、RPC、HTTP、嵌入式解释器或旧 CLI 执行业务。
3. **业务状态仍归 ForgeLoop**：需求／版本、分析、任务包、批准绑定、失败轮次与授权、
   工时、动作身份、证据与验收材料保存在插件控制的 SQLite；DSH 会话与投递回执不替代
   这些业务事实。
4. **DSH 承担通用能力**：会话、模型、工具、显示、权限与进程生命周期交给宿主；插件只
   保留必要业务命令、只读工具与持久工作服务。不新建聊天壳，不嵌入旧网页。
5. **执行使用真实 DSH Agent**：分析、规划、实现、独立审查都在本进程创建独立会话运行。
   - 分析与规划/审查阶段不授予工具，避免无界探索；提示词只提供事实与边界。
   - 实现阶段在**包含未提交在途改动的独立快照副本**中运行，授予工作区写权限；
     不允许改产品主工作树，也不创建产品提交。
   - 审查使用新会话、无工具、独立目录，只对固定候选 diff 作判断。
6. **持久工作由插件内协调器承担**：请求先落库再返回身份；确定性代码领取、去重、停止；
   宿主重启把未收口请求标为 `unknown`，未收口动作标为 `interrupted`，不盲目重放。
7. **旧实现退役但不追溯改写历史**：Python 源码、旧前端、旧测试与旧脚本移入明确隔离的
   `legacy/` 快照，不参与构建、检查或运行；Git 历史与既往验收记录按当时事实保留。
   旧记录库通过兼容表结构由 TypeScript 直接读取；迁移只在副本上演练并保留原件。
8. **质量门禁迁移而非删除**：`make check`、架构／CLI 契约、提交策略校验与数据迁移辅助
   改接 TypeScript 工具链；不降低原规则含义，不以“已删除 Python 检查”代替迁移。

## 后果

- 收益：交互与会话基础设施不再自建；安装形态是标准 npm bundle；业务记录与规则集中到
  一处可测试的 TypeScript 实现；宿主内 Agent 执行可复用宿主模型、工具与权限。
- 成本与风险：
  - DSH 仍是 developer preview，升级可能破坏插件兼容；本轮以 `engines.dsh` 与本机
    0.2.1-rc.2 验证，不承诺跨版本稳定。
  - 宿主进程内持久工作不具备跨进程事务；外部副作用（Git、部署、发布）仍需人工核对，
    未知结果不自动重放。
  - 独立审查的“受控访问”在本轮是“独立会话＋无工具＋固定 diff”；OS/容器级隔离未接入，
    不能声称已具备不可信工作负载的完整安全边界。
  - 旧 Python 的真实模型闭环、邮件入口、热升级等能力不在首版逐项移植；未验证项在状态
    文档中如实标记，不把“已退役”写成“已迁移”。
- 回退：旧实现保留在 `legacy/` 与 Git 历史；V0 安装包与记录副本保留，可按文档恢复。
  已产生的业务记录不因回退删除。

## 未在本 ADR 决定的事项

- 公开分发、许可、Plugin Market 上架与多租户；
- 邮件／IM 渠道的重新接入；
- 容器化或 OS 级审查隔离；
- 数据库引擎更换或远程部署形态。
