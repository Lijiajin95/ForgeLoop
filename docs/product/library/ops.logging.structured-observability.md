# 运行日志结构化与可追溯

## 业务目标
让运维和研发能快速定位一次请求或动作的失败原因

## 用户与角色
- 运维人员
- 插件使用者
- 协调器

## 触发与前提
插件运行、运行身份初始化失败或协调器发生关键异常时

## 预期行为
系统写入带级别的结构化日志；异常记录包含事件、请求标识、动作标识和错误栈；运维可通过内建只读入口读取日志尾部；可按级别过滤，并保留文本格式兼容。

## 业务规则
- 运行日志默认采用结构化记录，不应只依赖面向人的自由文本。
- 协调器关键异常必须携带事件、请求标识、动作标识和错误栈。
- 运行身份初始化失败也必须进入统一日志，不得只输出到控制台。
- 日志读取入口为内建只读制品，不依赖额外制品配置。
- 日志级别过滤生效，文本格式仅作为兼容选项。

## 例外与边界
- 日志读取入口不可用时，不应影响主流程运行。
- 级别配置非法时应在装载期拒绝，不得静默降级。

## 可观察验收
- 运维无需额外配置即可读取最近日志尾部。
- 按请求标识或动作标识可关联到同一次失败的关键异常记录。

## 适用范围与版本
ForgeLoop 插件运行日志，2026-11 版本
