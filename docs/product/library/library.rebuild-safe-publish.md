# 重建发布保护现有库与人工改动

## 业务目标
避免自动重建破坏已有需求内容与人工维护成果

## 用户与角色
- 项目所有者
- 需求维护人员
- 需求分析人员

## 触发与前提
重建候选通过审查，进入发布阶段

## 预期行为
系统只写入与现有库存在差异且未被人工改动的条目，对冲突条目保留原内容并记录冲突结果。

## 业务规则
- 发布前不得改动现有需求库。
- 写入前核对目标内容未被外部改动，不一致时放弃写入并保留原内容。
- 人工修改或已确认条目不得被自动覆盖，只能记录为冲突。
- 发布清单记录条目身份、摘要与内容指纹，作为重跑幂等与人工改动保护的依据。
- 写入失败不得留下半成品。

## 例外与边界
- 目标内容在重建期间被改动：放弃该条写入并保留原内容。
- 人工改动与候选冲突：保留人工版本并在报告中呈现冲突。

## 可观察验收
- 重建完成后，人工改过的条目仍保持原样，冲突可在报告中查看。
- 对未发生变化的条目重复重建，不会产生重复条目或内容变化。

## 适用范围与版本
需求库重建的审查与发布阶段
