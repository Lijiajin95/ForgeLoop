# 需求库一键重建并直接生效

## 业务目标
降低需求库维护的人工输入成本，让库内容随项目证据自动更新并可直接用于后续分析

## 用户与角色
- 项目所有者（发起与授权）
- 需求分析使用者（受重建结果影响）

## 触发与前提
所有者对某项目发起需求库一键重建

## 预期行为
系统启动重建，采集项目证据生成候选，按写库阈值写入重建条目或草案，完成后直接对后续分析生效。

## 业务规则
- 机器重建条目只需所有者一次授权
- 不要求所有者指定业务场景
- 不要求逐条确认候选
- 分析闸门按已有覆盖处理，所有者回答可取代该判断
- 重建有进行中、完成与取消状态，可中止
- 失败时给出确定性结果，而非静默中断

## 例外与边界
- 取消时停止后续处理并保留已完成结果
- 重建失败仍需返回明确结果与说明
- 所有者回答与自动判断冲突时以所有者回答为准

## 可观察验收
- 所有者点击一次后无需其他输入即可看到重建完成及生成的条目
- 重建进行中可查看状态并取消

## 适用范围与版本
需求库重建流程，当前实现
