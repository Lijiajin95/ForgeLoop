# 待澄清项阻断入队且问题编号稳定

## 业务目标
确保业务歧义由所有者回答后才进入研发，历史问题不因重新分析而消失

## 用户与角色
- 产品 Agent
- 业务用户（所有者）
- 运行时协调器

## 触发与前提
分析产生待澄清项，或所有者提交澄清回答

## 预期行为
有待澄清项时需求停在澄清状态；问题编号按首次提出的分析版本分配并保持稳定；回答追加需求版本并重新分析，必要时再次推送待澄清项。

## 业务规则
- 问题编号在首次提出的分析版本内稳定且只追加
- 未解决问题不会因再次分析而静默消失
- 只回答部分问题时其余问题仍阻断准入
- 回答绑定问题首次提出的分析版本与需求版本

## 例外与边界
- 问题输入不得带待澄清项
- 有独立需求时必须走明确的新需求入口

## 可观察验收
- 存在待澄清项时需求停在澄清状态而不进入研发队列
- 看板能逐题看到开放／已解决状态、历次回答与解决版本

## 适用范围与版本
需求澄清与入队，2026-11 版本
