# 重建取证按可核对时间从近到远

## 业务目标
让规则演进与适用范围有可回查的时间依据

## 用户与角色
- 系统（排序）
- 产品 Agent（判断适用性）
- 项目用户（查看覆盖）

## 触发与前提
重建开始分批取证时

## 预期行为
文档采用载明的决定、发布或修订时间，Git 使用提交时间，可归属版本的用例采用相应证据时间；每项证据记录项目归属、来源类型、版本或内容摘要及原始位置。

## 业务规则
- Git 是可选来源，无 Git 时继续使用本项目其他材料
- 同一时间的记录使用稳定的来源和位置顺序
- 日期更新或来源数量增加时，依据实际内容及范围判断规则是否变化
- 源码引用须记录文件、行段及代码版本或内容摘要，模型引用须对应本次已采集证据
- 结果显示实际覆盖的来源和时间范围，并列出缺失、跳过、失败及因预算未处理的部分

## 例外与边界
- 缺少可用证据时返回相应结果和原因，已有库继续可用

## 可观察验收
- 结果页显示本次实际覆盖的来源与时间范围
- 缺失、跳过、失败与预算未处理的部分单独列出

## 适用范围与版本
需求库重建的取证与排序，2026-11 版本
