# 不可复核或未验证的事项不得记为通过

## 业务目标
让读者区分已落实、未验证与未达成，避免把计划或历史记录当成现有能力。

## 用户与角色
- 产品 Agent
- 所有者
- 读者

## 触发与前提
记录一项限制、门禁或验收结论时

## 预期行为
系统按可复核材料判定并标注落实状态；缺失现场或未验证的条目按未达成或未落实记录。

## 业务规则
- 只有声明、没有强制机制的项必须标为未落实。
- 原始现场无法取得的条目不能作为已验证证据。
- 未在真实环境跑过的项不得声称已覆盖。
- Agent 不代签验收，也不自称验收通过。
- 证据归档失败时，运行必须以失败收口。

## 例外与边界
- 历史记录保留原文不改写，但判定以最新可复核材料为准。

## 可观察验收
- 打开验收汇总能看到每项判定、证据位置与复核方法，缺失现场的条目显示为未达成，汇总明确写未通过。
- 阅读门禁说明能区分已落实与未落实项，未验证项旁有明确标注。

## 适用范围与版本
文档、状态记录、验收汇总与门禁说明
