# 输入先分诊为需求或问题

## 业务目标
让缺陷修复不被扩写成新功能需求，使输入按真实业务意图进入正确路径

## 用户与角色
- 提交输入的业务用户
- 产品 Agent
- 研发 Agent
- 运行时系统准入

## 触发与前提
业务会话收到一条人类消息并进入产品分析

## 预期行为
分析结论在 input_kind 中标记为 requirement 或 problem，并在看板详情与会话分析卡片中展示；两类输入共用同一条需求记录与准入链。

## 业务规则
- 判断不定时按需求处理并进入澄清
- 问题分析只给现象与可检查的修复判据，不做需求拆解与产品澄清
- 问题修复过程不得把问题转成需求

## 例外与边界
- 带待澄清项的问题分析会被解析与落库拒绝
- 历史分析缺少 input_kind 时按需求处理

## 可观察验收
- 分析卡片与看板详情能显示该输入是需求还是问题
- 问题输入不出现产品澄清问题，而是直接进入研发修复

## 适用范围与版本
ForgeLoop 业务会话的人类输入，2026-11 版本
