# 普通需求不以所有者批准任务包为门禁

## 业务目标
让系统按真实证据自动推进日常研发，同时保留任务包作为可审计工作记录

## 用户与角色
- 研发 Agent
- 运行时协调器
- 业务用户（所有者）

## 触发与前提
需求通过准入后生成任务包，或任务包需要修改

## 预期行为
任务包落库后按流程推进；计划文件清单只作预期，不构成硬白名单；普通需求不等待所有者批准。

## 业务规则
- 任务依赖只表达真实前置关系
- 一个或多个任务均可组成任务包
- 方案是工作记录而不是批准门禁
- 任务数量不是验收覆盖的替代

## 例外与边界
- 历史兼容的方案批准记录不适用于普通需求
- 模型自报同意或 approved=true 不是有效批准
- 已批准任务包默认冻结，修改需所有者显式许可并说明原因

## 可观察验收
- 普通需求在任务包生成后无需所有者批准即可继续
- 任务包能列出覆盖的要点、依赖与限额

## 适用范围与版本
普通需求的任务包生成与推进，2026-11 版本
