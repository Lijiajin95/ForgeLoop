# 必须请求客户决定的六类例外

## 业务目标
只在真实业务例外处占用客户判断，其余按证据自动推进

## 用户与角色
- 业务用户（所有者）
- 产品 Agent
- 研发 Agent
- 运行时协调器

## 触发与前提
出现上述六类触发条件之一

## 预期行为
系统生成客户决定请求并暂停待决动作及其依赖，常规受理、实现、自验、独立测试与受控提交不逐阶段请求批准。

## 业务规则
- 技术难度高可在路线可行时仍请求决定，不要求先失败或耗尽尝试
- 重大架构变化以改变已确认的关键决策为准
- 遵循既有架构的跨模块功能不自动升级

## 例外与边界
- 系统准入未通过不属于客户决定
- 可自动恢复的技术失败与额度内缺陷修复不属于客户决定

## 可观察验收
- 触发例外情形时系统生成客户决定请求并暂停待决动作
- 常规缺陷修复不会因非业务原因升级为客户决定

## 适用范围与版本
日常研发与服务处置中的客户决策边界，2026-11 版本
