# 重建候选校验与已有条目保护

## 业务目标
在自动更新需求库的同时保护人工与已确认内容不被覆盖，并让超出容量的部分可追踪

## 用户与角色
- 项目所有者（授权）
- 需求库维护者（受结果影响）

## 触发与前提
候选生成后进入已有库审查与发布计划

## 预期行为
逐条比对已有条目，一致保留、指纹变化更新、摘要不一致视为人工改动保护；按置信度与证据数排序后发布，超出容量的进入溢出报告。

## 业务规则
- 候选校验覆盖标识、主题、摘要、角色、验收、证据与置信度
- 正文超过库读取上限的候选直接拒绝
- 内容指纹与运行标识和时间无关，用于判断同一规则是否变化
- 已确认或人工条目只记录冲突，不自动改写
- 整库容量有上限，超出部分进入溢出报告
- 重跑整体替换重建内容，且同一输入重跑幂等

## 例外与边界
- 候选校验不通过直接拒绝，不进入发布
- 摘要不一致不自动更新，按人工改动保护处理
- 超出容量不静默丢弃，而是记录在溢出报告中

## 可观察验收
- 重建后已有确认条目的内容保持不变
- 发生变化的条目可看到指纹变化依据
- 超容量条目在报告中可查

## 适用范围与版本
需求库重建的审查与发布阶段，当前实现
