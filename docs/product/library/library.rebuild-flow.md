# 存量项目可以一键重建需求库

## 业务目标
让缺少完整需求文档的存量项目也能获得可追溯、可维护的需求库

## 用户与角色
- 项目所有者
- 需求分析人员
- 研发与验证角色

## 触发与前提
所有者从看板对某个项目发起一键重建

## 预期行为
系统采集项目材料，按时间批次提炼候选需求，结合现有需求库审查后发布，并记录运行阶段、处理计数与结果。

## 业务规则
- 重建必须依次经过取证、提炼、审查、发布四个阶段，审查不得省略。
- 提炼只使用本批次证据与现有需求库索引，不引入其他来源。
- 单批提炼失败只记录错误，其他批次继续。
- 每次运行必须留下可回查的报告与发布清单。

## 例外与边界
- 模型单批失败：记录错误后继续整轮。
- 需求库状态损坏：运行失败，不发布任何内容。
- 增量重建、源码入口识别、漂移检测与真实模型验收尚未纳入本规则。

## 可观察验收
- 所有者能在看板发起重建，并看到运行状态与最终结果。
- 运行结束后可查看本次报告与发布清单。

## 适用范围与版本
已接入需求库的存量项目；增量重建、源码入口识别与漂移检测的范围待确认
