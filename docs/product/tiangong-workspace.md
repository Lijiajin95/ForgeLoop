# 天工 · 四个标签页的布局与交互设计

研发交付规格 · 2026-11-18 · 批次 1–3 已实施（批次 4 待实施）

[打开可点击的界面设计稿](tiangong-workspace.html)（浏览器本地打开即可，内含四页、三种工作台视图和独立详情窗口）。设计稿使用示例数据，点击导航和带 ↗ 的入口可对照下文；数据操作、统计与刷新按规格实现。需求入口见[产品与首版方案 §8.1](product.md#81-客户入口与业务工作台)。

采用「工作台、产品、度量、运维」四个一级标签。「按需求」和「按任务」是工作台内的浏览方式，「需要处理」是全项目研发待办队列。下文线框中的示例文案用于说明布局，数量及异常状态以实际记录为准。

## 共同框架

```text
对话    轨迹    天工
天工   ForgeLoop                        上次读取时间   刷新   自动刷新
工作台     产品     度量     运维
────────────────────────────────────────────────────────────
本页工具栏
本页主体
```

宿主导航负责切换工作环境，项目栏显示当前项目和本页读取状态，一级导航下面才放对象搜索、状态筛选和业务操作。取消跨页常驻的需求树和五项统计大卡。首页若需展示规模，在需求选择器或列表标题处就近写“4 个需求”或“1 个任务”。产品页的数量用条目数，运维页用事件数。

进入天工后，四页和工作台内的三个视图均隐藏宿主输入框、发送和附件控件、模型选择、Token 统计以及底部占位。回到对话时恢复草稿与附件。刷新作用于当前数据源；支持持续更新的页面显示自动刷新，单次读取的页面仅显示刷新。失败时保留上次成功内容，并标明读取时间。

## 一、工作台

### 按需求 · 看清产品、研发与验证的对应关系

```text
[按需求]  按任务                                  需要处理 N 项
选择需求 ▾   把可靠性标签页名称修改为度量       研发中   查看详情 ↗
────────────────────────────────────────────────────────────
产品要点                   研发任务                  候选验证
已形成说明                 0 / 1 已交付              尚无结论
BP-1  页签显示为「度量」    rename-metrics-tab 执行中   核对页签名、标题与无障碍名称
验收要点                   覆盖 BP-1                 最近异常
标题与无障碍名称一致        Agent 执行过程 ↗           测试方案生成失败
产品 Agent 执行过程 ↗                                验证 Agent 执行过程 ↗
```

- **布局。** 顶部仅一行需求上下文。选择器支持按标题或身份查找，每个候选项显示短标题和总状态。主体宽度建议按 30%／36%／34% 分配，给最长的任务列表更多宽度，同时让验证状态在首屏可见。三列各有独立标题、阶段状态和执行入口。整条需求的停止、取消等操作收在标题旁的操作菜单。
- **多对多映射。** 产品列每个业务要点一行，带简短验收条件。选择一项后，研发列突出显示声明覆盖它的任务，验证列突出有明确关联的场景；保留其他行并提供“显示全部”。跨多项的任务只列一次。需求级验证归到候选名下。旧记录无法回指业务要点时，列在“尚未关联”下，仍能查看记录。
- **首屏取舍。** 任务行显示短目标、状态、覆盖编号和轨迹入口。验证列优先显示本次结论和首条阻塞原因，其后显示有记录的场景摘要。多项任务或场景时，点击“显示其余 N 项”就地展开同类列表。长说明、原始报告和历史轮次走详情窗口。
- **状态读法。** “测试方案生成失败”可与“尚无验证结论”并存；有当前候选的失败报告才显示“验证未通过”。旧报告显示“需重新验证”，附历史入口。正在读取、读取失败、成功读取但无记录分别呈现。产品或验证没有可读 Agent 记录时，在该阶段说明缺项，避免链接跳到研发日志。
- **窄屏。** 标题下先列产品、研发、验证三项状态摘要，点击可跳到对应区块；正文按阶段纵排。即使任务很多，用户打开页面也能先看到验证结论。

### 按任务 · 跨需求扫描研发进度

```text
按需求  [按任务]                                  需要处理 N 项
按需求筛选任务              所属需求 ▾   状态 ▾   清除筛选
任务目标／编号        所属需求        执行状态    阻塞或等待项    最近活动    操作
更新页签显示名称       页签改名        执行中       —             时间        过程 ↗
```

任务目标是首列主文字，任务编号为辅助文字；列尾固定「Agent 执行过程 ↗」，任务标题打开详情。点击所属需求切回“按需求”并定位该任务，返回任务视图保留筛选和行位置。默认将阻塞和待输入列在前面，同组按最近活动排序。若现有检索只能按需求匹配，应明确标为「按需求筛选任务」，任务级搜索待具备对应检索后启用。自动刷新时保留正在阅读的行和键盘焦点。窄屏每个任务占两行，第一行放目标与状态，第二行放需求、阻塞原因和操作。

### 需要处理 · 决定下一步

```text
‹ 返回按需求        需要处理                         范围：当前项目
全部阶段 ▾   仅阻塞 □
优先程度    原因                 影响对象／阶段         可做的下一步
阻塞        测试方案生成失败      页签改名 · 验证        查看验证过程 ↗
待输入      尚有待澄清事项        对应需求 · 产品        查看待澄清项 ↗
```

点击右上入口后，队列占用主体全宽。返回键显示来源视图，原需求选择与任务过滤条件保留。队列总数独立于这些条件。每行先给出可理解的原因，再给出所属需求、任务或验证候选，最后给出一个具体动作。相同对象、阶段和原因有可核对关联时才归为一项；多种原因分别保留。重复次数与历次报错进详情。只提供服务端当前允许的操作，可用信息不足时保留查看证据入口。提交重试后显示受理状态；只有新记录证实问题消失才更新队列。运维事件留在运维页，已生成的研发修复需求可从这里回查关联。

## 二、产品 · 查找项目采用的需求与决策

```text
产品需求库                                              重建需求库
搜索条目标题或摘要                     全部状态 ▾   最近更新 ▾
主题目录                 条目标题、摘要                          状态
全部条目                 标题                                    已确认
主题 A                   一至两行摘要                    查看详情 ↗
主题 B                   主题 · 更新时间
                         ──────────────────────────────────
                         下一条条目                              草稿
```

- **桌面布局。** 左侧约 200px 主题目录由实际条目生成；右侧是单栏阅读列表。标题最醒目，摘要最多两行，状态紧邻标题；主题与更新时间为辅助信息。默认展示当前条目，已被取代的条目可通过状态筛选找回。筛选无命中时保留目录并给出清除条件入口。
- **阅读路径。** 标题和「查看详情 ↗」通往同一个条目窗口。窗口先展示正文，再给来源、引用、更新时间及可取得的修订记录。引用正文截断或读取失败时在正文处标明，提供已有来源或重读入口。正文阅读宽度建议控制在每行 35～45 个汉字。
- **重建路径。** 将「重建需求库」与检索分开。运行时在列表上方显示一条进度带，含取证／提炼／核对／发布中的当前阶段、批次进度和「Agent 执行过程 ↗」。完成后展示本轮草案及冲突、未决数量；先查看本轮候选范围，再使用已有的「确认本轮草案」。失败时仍可浏览已有条目。草稿状态属于条目，运行状态属于重建批次。
- **窄屏。** 主题目录收成一个选择器，条目变成纵向阅读列表。切主题、阅读正文、关闭窗口后都能回到原条目。

## 三、度量 · 解读工程质量与交付表现

```text
度量                 测量截至 [时间] · [快照状态]       查看测量详情 ↗
工程质量 · 本次快照
[质量结论与首要原因]               门禁通过数    测试结果    行覆盖率
门禁名称                 状态            实测／门槛           查看证据 ↗
────────────────────────────────────────────────────────────
交付表现 · 统计窗口                             7 天  30 天  90 天  [全部]
验证通过         首轮通过         业务终审         上线核对
通过数／总数     通过数／总数     通过数／总数     通过数／总数
趋势图与数据表入口                         相关事件 · 对象详情 ↗
```

- **先辨时间，再读数字。** 第一层是固定提交、固定时刻的质量快照，第二层才应用统计窗口。测量截止时间和页面最近读取时间各自标明。窗口控件靠近交付指标；切换窗口后显示实际起止日期。固定周期的趋势图在图题写清自己的周期。
- **首屏决策。** 快照区先显示质量结论和影响结论的首要原因；未达门槛项置顶，同行给出实测值与阈值。查看证据新开窗口，展示测量点、提交、执行命令和可取得的原始证据。完整覆盖率、逐文件结果、变异与预算由对应指标下钻。
- **图表。** 每个率值同屏给出分子、分母；小样本使用文字提示。趋势图保留单位、时间刻度和可用键盘打开的数据表。点事件进入绑定的需求详情，主页面保留窗口和图表位置。读取本页只查看已有测量记录。
- **缺数与窄屏。** 未采集、不可读、已过期、无样本分别显示。快照过期仍可回查当时结果；快照缺失时，交付记录若仍可用，标明实际截止点。窄屏顺序为质量结论、异常门禁、交付表现、趋势；比例和样本量始终相邻。

## 四、运维 · 按业务影响处理事件

```text
运维事件          主动监控状态 · 最近扫描时间               监控详情 ↗
[处理中]   全部           严重度 ▾    处置状态 ▾
严重度   事件／业务影响             资源        处置状态        最近更新
严重     事件标题                   资源名称    待决定          时间
         一句话说明受影响的业务                                  查看详情 ↗
重要     下一起事件                 资源名称    恢复核对中      时间
```

- **列表布局。** 监控仅占顶部一行。采集异常或过期时展开一行原因。CPU、内存、负载、来源与心跳进监控详情。事件列表占主体全宽，标题下给业务影响；尚未诊断时写「影响待确认」。严重度和处置状态分列。默认看处理中，组内先按严重度、再按最近更新排序，可单独筛待决定。
- **事件窗口。** 顶部固定事件名、受影响资源、严重度和当前处置状态。正文依次是业务影响、已观测事实、诊断推断与依据、建议动作及其作用对象、处置记录、恢复核对。Agent 分析有记录时给出过程入口。动作中断时展示“执行中断，结果待核对”和已取得的证据。
- **操作位置。** 「批准处置／拒绝处置」紧随具体建议；「关闭事件／生成修复需求」放事件操作区。确认时再次显示目标资源和动作。受理后显示“等待协调器处理”，拿到实际执行和恢复记录后再更新结论。已生成修复需求时显示关联入口；用户可直接去工作台查看研发与验证。
- **窄屏与空态。** 每个事件第一行标题和严重度，第二行业务影响，第三行资源和处置状态。处理队列为空写“当前没有处理中的事件”，可切历史。监控未启用或本次读取失败时另行提示，避免被理解为系统健康。

## 详情窗口与视觉规范

| 层次 | 共同行为 |
| --- | --- |
| 主导航与页标题 | 沿用宿主字体与主题色。一级导航用下划线和字重标明当前位置。页标题约 20px、段标题 16px、正文 14px；窄屏优先保留对象名和文字状态。 |
| 间距与对齐 | 8px 为基本间距，筛选组间 16px，业务区块间 24px。任务与事件表格给状态和操作稳定列宽，标题弹性换行。详情长文限制行宽，主界面仅一个主要纵向滚动区。 |
| 状态与风险 | 蓝色表示进行中，琥珀色表示需要关注，红色表示明确失败或严重风险，绿色表示有依据的成功。每个颜色带文字。文档“已确认”、研发“已交付”、候选“验证通过”各用本领域词汇。 |
| 开窗与返回 | 「查看详情 ↗」打开对象概览，「Agent 执行过程 ↗」直接打开对应阶段与尝试。标题带项目、对象及所属阶段。主页面切换选择后，已开窗口继续展示原对象；关闭后焦点回到发起控件。弹窗被拦截时给出可点击链接。 |
| 自适应 | 以工作区可用宽度判断布局。建议从 1200px 起用完整三列；820～1199px 将需求映射改为产品与研发并排、验证横跨全宽，并把验证状态放在需求标题旁；低于 820px 单列。模糊的热点、仅悬停可见的按钮由显式按钮替代。 |

## 评审核对

1. 选中截图示例需求，首屏能看到执行中、0/1 已交付、验证尚无结论和方案生成失败；三条轨迹入口分别绑定正确阶段。
2. 从某需求切到按任务，筛出阻塞任务，再打开全项目待办；能找到其他需求的待办，关闭队列后回到刚才的任务过滤条件与位置。
3. 产品库读取或重建失败仍能回看已有条目；查看本轮草案后，用户能指出确认动作影响的是哪一批。
4. 度量从“全部”改为“7 天”，能指出哪些结果按窗口重算、哪项快照绑定固定提交，以及读到的比例来自多少样本。
5. 处置请求已受理但未完成时，运维页能区分待决定、执行中、执行结果和恢复结论；从修复需求能追到研发与验证。
6. 桌面和 390px 窄屏切遍四页，底部无会话框、Token 条或遗留占位。键盘能切视图、打开详情并返回；回到对话时草稿仍在。

## 实施边界

本稿用于研发实施，示例均为设计数据。实施前需核对 DSH 会话壳层能否按活动视图控制底栏、详情窗口如何继承会话身份，以及产品和验证阶段可展示哪些真实执行记录。研发任务已有过程入口；历史资料缺失时显示具体缺项。度量沿用现有质量快照与交付统计口径，运维沿用现有服务端动作条件。依据为所给界面截图、ForgeLoop 工作台客户端与架构说明，以及 DSH 会话布局源码。

## 研发交付清单

### 视图身份与操作约定

| 位置 | 初始值、键与转移 |
| --- | --- |
| 一级导航 | 第一次进入选工作台，复用 `hierarchy` 作为工作台入口；`product`、`reliability`、`ops` 保留。导航顺序固定为工作台、产品、度量、运维。已有跳往 `tasks`、`issues` 的调用改为工作台相应视图，读端点名 `reliability` 保留。 |
| 工作台 | 默认按需求，优先恢复本项目上次选中的有效需求，否则取可见列表首项。筛选结果为空则显示清除筛选入口。任务定位键为项目、需求、任务包版本和任务 ID；同名任务不可跨需求串联。 |
| 待办返回 | 打开队列前记录来源模式、原对象、搜索、排序和首个可见行。切入队列只应用队列筛选；返回恢复来源。记录已消失时定位最近仍可见的行。 |
| 页面状态 | 按项目与视图隔离。自动刷新复用相同对象键，晚到的旧请求不得覆盖新选择；切换到另一项目时清掉原项目选择。加载中不给 0，刷新失败显示旧值及其时间。 |
| 详情窗口 | 由用户点击同步发起新窗口或新标签。入口绑定项目上下文、对象类型、业务身份、分区；阶段历史再绑定尝试或候选。新窗口自行读取并校验当前会话可见的数据。URI 只携带定位所需身份；认证复用宿主同源会话。对象失效、不可访问或弹窗拦截时给出对应状态。 |
| 键盘与窄屏 | Tab 切到导航组、视图控件、行链接；标签组支持方向键，Enter 激活。新窗口链接有可读的“在新窗口打开”说明。关闭后焦点回发起控件；对象已消失则回列表标题。390px 下避免整页横向滚动。 |

### 前后端取数与缺口

所有端点名均指既有认证路由 `/api/forgeloop/board` 请求体中的 `endpoint`。以下将现有读取能力与本轮需补的只读投影分别列明。具体字段以[看板读模型](../../packages/forgeloop/src/runtime/board.ts)、[路由](../../packages/forgeloop/src/runtime/board-route.ts)和[需求投影](../../packages/forgeloop/src/runtime/requirement-views.ts)为准。

| 界面对象 | 已有依据 | 实施要求 |
| --- | --- | --- |
| 产品要点与覆盖 | `detail.analysis.businessPoints`、`acceptanceItems[].pointIds`、`detail.latestPlan.tasks[].covers` | 只在需求版本、任务包与记录相符时关联 ID。旧规格仅有自然语言时显示原目标和验收摘要，归为“尚未关联”。 |
| 研发状态与过程 | 看板任务实际状态、`progress`、`task` 和 `execution`；过程已有分页、尝试选择、暂停与工具输出展开 | 复用现有过程视图及终态规则。历史记录缺失时保留不可用说明；已取消需求的历史任务不进入交付进度分母。 |
| 候选验证 | 看板 `verification.verdict/fresh/candidateSha256` 及 `detail.verification.scenarios` | 先判断绑定是否有效，再解释 pass／block。仅对已有可靠关联的场景标覆盖；若报告只有场景文字，则显示在候选层级。允许自验的交付路径须标证据来源，有记录时展示自验结论；缺独立报告不能据此推断失败。 |
| 阶段轨迹 | 仓储已有 `analysisAttempts(reqId, requirementVersion)` 与 `verificationAttempts(reqId)`；需求详情已有分析历史与验证摘要 | 补两个独立的阶段活动投影。分析按版本、尝试、时间展示公开结果和已记录工具名；验证按需求版本、任务包、候选和尝试绑定结论、阻塞项及会话。尚未形成报告的测试方案异常只引用能确认阶段的失败记录。记录摘要、公开事件和完整逐步轨迹按实际可读性标识。 |
| 全项目待办 | `board.issues` 取自匹配且截断后的需求集合，返回问题列表也有独立上限 60；`summary.issues` 当前来自该列表 | 在同一项目权威记录上先聚合、再分页，供入口计数和队列共用。建议增加同路由只读 `attention` 分支，返回总项数、筛选后项数、稳定排序的当前页与下一页标记。排序建议为优先程度、最近记录时间、稳定身份。同任务不同故障保留两条，身份缺失时以原 issueId 分列。 |
| 产品 | `library`、`library-entry(entryId)`、`library-rebuild-status`；重建、取消、确认已有独立动作 | 列表搜索标题与摘要，主题来自条目。确认绑定本轮 runId。切页重进查询该轮状态；查看过程读取批次记录。 |
| 度量 | `reliability(window)`，已有快照状态、测量截止、运行汇总、趋势、关联事件、revision | 保留全部／7d／30d／90d 与既有口径。刷新以窗口及 revision 判定显示内容；下钻固定原测量点，资料已更新且旧样本无法取得时提示重新选择。详见[度量现行设计](reliability-dashboard.md)。 |
| 运维 | `ops`、`ops-detail(eventId)`，已有建议动作和处置结果 | 读写入口继续按事件身份、状态与既有规则校验；批准、拒绝、关闭、生成修复需求都关联原事件。监控成功采集到的 0 与无观测分别展示。 |

### 测试先行的验收样例

| 编号 | 给定／操作 | 独立预期 |
| --- | --- | --- |
| W1 | R1 的 BP-1 被 T1、T2 覆盖；R2 有同名 T1；R1 有一条无显式关联的验证场景。点击 BP-1 | 仅突出 R1 的两项任务，未关联的场景仍可见；研发轨迹请求带 R1 及对应任务包版本。 |
| W2 | 同一需求依次使用无报告、当前 pass、当前 block、旧候选 pass、计划生成失败五组材料 | 分别显示尚无结论、验证通过、验证未通过、需重新验证、尚无结论并显示计划异常。最后一组不得出现“测试未通过”。 |
| W3 | 项目有 101 个需求及超过 60 条有效待办。按某需求搜索，只命中 1 项，再开队列翻页 | 项目总数来自未受搜索限制的聚合；最后一页仍可定位末项。同一任务的两种原因分别可见。返回后恢复原搜索条件。 |
| W4 | 从按任务打开 T1 详情，再在主窗口选择 T2；模拟旧读取后到、对象删除、开窗受限 | 原窗口保持 T1；晚到响应不污染 T2；删除后显示失效，受限时有用户可点击的备选链接。 |
| P1 | 打开一条已有正文和一条引用不可读的库条目，运行重建后切离再返回 | 前者显示正文，后者显示原因。重建进度绑定原批次，可查过程；完成后只对该批次提供确认入口。 |
| M1 | 固定质量快照，准备 7 天与全部窗口内不同数量的验证记录，再换到无样本窗口 | 快照提交、时间及门禁不变；窗口累计和样本量随真实记录变化。分母为零时显示无样本。 |
| O1 | 待决定事件依次收到处置请求受理、执行完成、恢复核对三条记录；再试一次无扫描数据 | 界面按实际阶段更新；仅受理时不能宣告恢复。无扫描数据展示缺项，避免误显正常或 0%。 |
| S1 | 在对话中留下未发送文字和附件，进入四页，开一个独立窗口，再切回对话；桌面、390px 及键盘各走一遍 | 天工没有底栏、Token、隐藏焦点或空白占位，草稿与附件仍在。关闭详情回到发起控件；390px 能在首屏读到三个阶段状态。 |

验收证据包括上述正常与拒绝路径的行为测试，以及在真实 DSH 会话中的导航、开窗、刷新、返回与窄屏核对。工程检查按 [AGENTS.md](../../AGENTS.md) 执行。本设计稿可用于对照布局，工程通过与宿主场景验收由实施批次记录。
