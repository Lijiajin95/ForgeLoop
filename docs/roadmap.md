# ForgeLoop RoadMap：先跑通，再扩展

日期：2026-10-12，Asia/Shanghai。状态：快速启动重排；各阶段尚未实际执行。

原先 M0 状态页、M1–M3 全部完成才算正式首版的安排被替代。当前先完成 [CLI 首版](product-requirements.md)，后续按[待实现需求列表](pending-requirements.md)选择。审查与理由见[五步工作法审查](requirements-review.md)。

## 1. 当前只排一个版本

| 阶段 | 交付 | 前进条件 |
| --- | --- | --- |
| 启动检查 | 最小环境、一个 PI 真实调用、事件与会话落盘 | 真实调用有结果；明确容器、模型、协议和基线问题 |
| CLI 首版 | LangGraph 串联批准、实现、自验证、独立审查、正式测试和人工验收 | 一个真实小任务产出可验收 diff 与记录 |
| 开始使用 | 完成 3–5 个真实小任务，记录人工时间与返工 | 用实际收益与痛点选下一项，首版不等待整个目标平台 |

保留首轮三十小时人工投入上限。成功后即可使用，不用为了填满预算继续添功能；上限到达而未完成，汇报缺口，再决定续投或进一步删减。

## 2. 下一项由痛点决定

| 实际痛点 | 候选需求 |
| --- | --- |
| 查询或异步批准不便 | B01 页面或 B02 邮件，先选一个入口 |
| 人工接回代码耗时 | B04 main 受控自动归并 |
| 稳定人工发布需要自动化 | B05 发布，再按风险实现 B06 运维与 B13 备份 |
| 长任务停下后经常需要续跑 | B08 安全点暂停、B12 恢复 |
| 多项工作积压 | B09 调度、B10 任务拆分 |
| 现有测试覆盖不了实际问题 | B11 测试 Agent 与完整场景 |
| 第二个业务图有重复代码 | B15 抽共享包 |
| PI 确有不可补足的能力缺口 | B21 新执行器，或评审 B22 自研 Runtime |

这些是选择路径，不是必须依次完成的模块计划。生产相关需求进入实施时，原本的版本、授权、验收产物和恢复原则随对应需求启用。

## 3. 后续候选管理

待实现列表记录每项的触发条件、依赖与验收要求。只将被选中的一项拆成当前工作，不一次性开发全部 P1／P2。

自研 Runtime、更多框架、MCP、多节点、长期记忆、桌面控制和主动需求／重构不会因“以后可能需要”进入当前首版。自动压缩直接复用 PI；专项质量扩展由实际长任务问题触发。

## 4. 验证价值

先证明系统交付真实代码，再观察 3–5 个真实任务。记录澄清、批准、验收、人工接回、故障和维护时间；基线区分历史实测与执行前估算。

人工接回和部署是首版有意保留的人工步骤，也要计入成本。若它们成为瓶颈，再自动化，不把“已经自动化很多环节”当作净收益。
