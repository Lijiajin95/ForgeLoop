## 2. 版本规则

- V0／V1 是角色名；实际包版本、tarball 摘要与安装 profile 必须记录在状态与交付说明中。
- 稳定运行的版本与被修改的候选目录分开：V0 从安装包运行，候选源码在独立快照中开发。
- 每次升级保留旧 tarball、`artifact.json` 与记录副本；恢复不依赖新版本损坏的现场。

## 3. 前进条件

M1 完成后不自动进入 M4。先按 M2 证明持久执行，再按 M3 补工程门槛，最后由所有者根据真实
使用痛点决定是否投入渠道、发布或运维能力。任何“平台化”扩建都需要独立方案与授权。

## 4. 历史

旧 Python／Web／serve 路线与 G01/G02 记录保留在 Git、`docs/history/` 与 `legacy/`，按当时
事实不追溯改写；它们不再是当前路线的验收依据。
