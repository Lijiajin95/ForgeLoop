# ForgeLoop 测试、质量门槛与 Lint 完整方案

日期：2026-10-13，Asia/Shanghai。状态：**实施提案，尚未启用新增规则或提高配置门槛**。本轮只新增本文，不修改源码、配置、工作流或既有记录，不创建 commit。

本方案首先服务真实小任务闭环，再按风险加强自动化验证。容器隔离后置实施，但仍保留为首版执行边界的未完成项；受监督实验通过不能提前记为权限隔离通过。

## 1. 范围、权威来源与实施原则

当前有效数值仍由 `config/quality-policy.toml`、`pyproject.toml` 和执行脚本决定。本文的“目标”只有在对应批次评审、实现、负例验证与记录更新完成后才成为有效门槛。届时同步修订 `docs/engineering-reliability.md` 的方法和阈值，保留历史执行记录；`docs/status.md` 继续是当前状态唯一入口。

**2026-10-13 晚的门槛精简已实际生效**：结构数字（函数行数、文件长度、公开接口数、复杂度、参数数、分支数）改为审阅提示，Ruff `C901`/`PLR0912`/`PLR0913` 与 Pylint 的两项检查停用；变异清单的过期已审条目改为提示；CI 不再在同一作业内重复运行高频套件；CLI 状态读取失败改为报到 stderr。记录见[工程可靠性方案第 25 节](engineering-reliability.md#25-可靠性门槛精简结构数字转提示变异清单提示化ci-去重与状态读取可见2026-10-13-晚)，本文第 6.2、7.1、9 节已据实更新。这些改动**没有**启用本文的 95% 覆盖、逐文件 100%、新增 Ruff 规则或全量属性 1000。

产品范围以 `docs/product-requirements.md` 为准。`docs/dogfood-execution-plan.md` 中新增需求规划、并发和交付能力按其独立批准推进；本文不提前授权这些业务。原首版验收 A01–A05 在本文记作 **V-A01–V-A05**，避免与 DogFood 任务 A01–A05 混淆。

实施遵循：

1. 先完成有实际用途的真实小任务。新增质量措施不成为无限延期该任务的理由。
2. 关键判断、计算、状态流转和幂等逻辑先运行失败的行为测试，再实现；环境错误不作为目标行为的失败证据。
3. 测试观察公共行为、记录和副作用，预期来自批准需求；不复制实现计算预期，不以私有调用次数作为主要契约。
4. 替身用于确定性流程和故障构造；真实协议、安装、权限和恢复结论需要真实边界证据。
5. 先扫描和报告，再审阅命中，最后启用门禁；每项硬门槛有正例和可重跑负例。
6. 文件范围按第 12 节分批确认。架构变化同批更新 `docs/architecture.md` 与 `contracts/architecture.json`；CLI 契约变化同批更新对应快照。
7. 本方案不授权提交、推送、创建标签、发布、部署或修改分支保护。已有同批授权可按原范围使用；提交仍遵守实际提交策略与日历。

## 5. 故障注入与协议测试的最小矩阵

| 故障／输入 | 注入位置 | 必须观察的结果 |
| --- | --- | --- |
| PI 启动失败或接受 prompt 后退出 | 真实子进程边界 | 明确错误、stderr 留存，不产生虚假候选成功 |
| settled 后最终文本缺失、错误 id 或响应超时 | RPC fixture／真实协议接缝 | 不读取别的请求结果；结果缺失明确中断 |
| split frame、非法 JSON、缺 type、错误字段类型 | RPC 字节流与审查结果 | 合法分段被重组，非法输入按既有／批准契约处理，不崩溃放行 |
| abort 未确认、进程忽略正常关闭 | 可丢弃子进程 | 超时／终止／强杀路径有事实依据；进程被回收；停止状态准确 |
| 正式测试超时 | 真测试子进程 | 超时与普通 exit 非零区分；日志保留；不伪装为正式测试通过 |
| GitHub 断连、非法响应、未知检查状态 | HTTP 测试服务／边界注入 | 重试次数或截止时间有界；归并保持拒绝／等待，不误放行 |
| 记录／报告写入失败 | 临时目录权限或写入接缝 | 失败可见，不返回完整交付成功；保留已存在原始材料 |
| 动作执行后、完成记录前进程中断 | 真 CLI 进程 | 标记未核对，禁止直接再次执行；不要求首版自动恢复 |
| SQLite 两连接争用／创建中途失败 | 临时真实数据库 | 在批准的 B03 原子性／重复启动任务中验证，无半条创建或双消费 |
| 激活、冒烟或恢复失败 | 临时安装前缀／真实恢复目标 | 指针和回执据实；遵循已批准恢复语义，不自行新增自动回滚 |

故障只作用于可丢弃副本和批准的目标，不耗尽宿主磁盘、不杀无关进程、不改真实系统时钟。内核故障、断电和广泛并发混沌测试后置；当前先验证上述明确失效窗口。

## 6. 数值门槛与统计口径

### 6.1 覆盖率

| 指标 | 当前有效门槛 | 拟启用目标 | 启用条件 |
| --- | --- | --- | --- |
| 高频全局行覆盖 | ≥90% | **≥95%** | V-A01 优先；补有效行为用例后 Q03 启用 |
| 高频全局分支覆盖 | ≥90% | **继续 ≥90%** | 先补关键异常分支；95% 作为后续评审目标，不同时上调 |
| 新增／修改行覆盖 | ≥90% | **≥95%** | Q03 先确认真实差异达标，再启用 |
| 当前核心领域 7 文件 | 全局门槛＋行为测试 | **逐文件行／分支 100%** | 测量可达性后 Q03 显式配置；无分支的文件记不适用；必要排除逐项审阅 |
| 关键流程判断 | 行／分支计数与场景验证 | **适用正反例缺失 0** | K01–K14 对应的已实现能力实际验证，不用总覆盖替代 |
| 全量覆盖（含真实安装） | 尚无独立报告门槛 | **行 ≥95%、分支 ≥90%** | Q05 新建同版本全量测量；不使用全量结果掩盖高频回归 |

口径与执行要求：

- 行覆盖 = covered_lines / num_statements；分支覆盖 = covered_branches / num_branches。比较原始计数，不对显示值四舍五入后判断；coverage.py 的混合总百分比不用作这两项指标。[coverage.py 官方说明](https://coverage.readthedocs.io/en/latest/branch.html)
- 高频继续覆盖完整产品源码，选用非 install 的单元、属性、组件、场景与协议集成；系统进程覆盖另行说明。真实安装分支仍在源码分母内，不能为提高数字直接移出。
- 全量报告在同一修订、同一源码内容和可核对环境下汇合适用层；保留高频与安装分测结果。安装的 wheel 与源码版本必须匹配，路径映射正确；未采集的子进程不能假称已覆盖。[coverage.py 数据合并说明](https://coverage.readthedocs.io/en/latest/commands/cmd_combine.html)
- macOS 与 Linux 分别过门禁。跨系统合并只用于观察，不能让一个系统覆盖的分支代替另一个系统的失败结果。
- CI 增量基线是对应 PR 的可信目标基线／merge-base，推送使用该次受控比较基线；显式记录 base SHA 与 head SHA。替换当前固定 `origin/main` 比较须在 Q03 先写失败测试；防止更新目标引用后差异为空却宣称通过。
- 没有可覆盖的代码差异记“不适用”，保留差异清单；缺 Git 基线、缺报告、计数非法、总源码计数为零或工具运行错误均失败。只在初始化无基线的已说明场景使用显式不适用。
- 核心文件清单固定为 `counting.py`、`approval.py`、`limits.py`、`commit_policy.py`、`merge.py`、`release.py`、`deploy.py`，均在 `src/forgeloop/domain/`。新核心模块由其业务方案纳入，不能漏测后仍沿用“全部核心”的表述。
- `pragma: no cover/no branch` 必须有可核对的不可达／等价理由、审阅者和重检条件；缺口是真实错误路径时补测试。100% 仍不证明断言正确或故障处理完备。

提高门槛本身几乎不增加测量成本；新增用例会增加执行与维护成本。9 行和 26 分支不等于 9／26 个测试。保持候选统计范围、有效断言和源码语义，不为了数字删错误处理或过度拆函数。

### 6.2 属性、变异、正确性与证据

| 指标 | 目标／判定 |
| --- | --- |
| 属性生成预算 | 本地 max_examples=100；CI 明确选 `forgeloop-ci` = 300；夜间／发布前选 `extended` = 1000 |
| 属性结果 | 失败 0；输出实际有效样例、discard、运行时间；失败保留最小反例与可用重放信息 |
| 当前核心变异 | 未审幸存 0，未完成 0，报告非空，计数闭合；真实行为缺口 0 |
| 幸存者审阅 | 区分等价、非行为文本和真实缺口，记录理由与源码身份；真实缺口必须补断言并杀死，不能仅登记放行。**过期条目降为提示**（2026-10-13）：旧已审条目被新测试杀死时只提示重导清单，不判整个变异检查失败；源码变化后仍须复核 |
| 一般模块变异 | 仅未来经评审选入的范围使用有效非等价 killed ≥90%；当前脚本尚未对一般范围应用该阈值，不提前声明启用 |
| 正式测试和关键用例 | 失败／超时／未完成 0；适用关键用例不可静默 skip 或 xfail |
| 真实任务证据 | 输入、批准、基线、候选、独立审查、真实测试、用户验收和交付记录，必需材料缺失 0 |
| 故障／停止／隔离 | 对已实现且适用矩阵，误报成功、授权越界、盲目重放 0；未实施权限隔离记未通过 |
| 记录／产物 | 身份错配 0，错误校验值放行 0；备份与恢复必须实际读取 |
| 报告身份 | 执行修订／源码摘要、工具版本、命令、环境和基线齐全；不以不同 SHA 的昨日通过代替当前检查 |

max_examples 是预算，有限输入空间可能少于该数，过滤和反例缩减也会增加执行；不是可靠性置信度或严格调用次数。操作序列初始最多 50 步，按反例与成本再校准。Q01 需验证 CI 确实加载 300 档位，Q04 验证扩展档位；扩展属性单独运行，不能无意中把变异作业也切到 1000 档位增加长跑成本。[Hypothesis 设置](https://hypothesis.readthedocs.io/en/latest/reference/api.html)

mutmut 当前原始 531/621 不能宣称 killed ≥90%；等价与非行为审阅也不能让新的真实缺口免检。保留可疑幸存者复测一次的机制：只对**未审阅幸存者**复测，两次结果都记录，确认仍不一致则失败；过期清单条目只提示复核、不触发复测；缺报告、空报告和未完成状态不靠复测放行。[mutmut 官方说明](https://mutmut.readthedocs.io/en/latest/)

### 6.3 时限、稳定性与资源

| 层／指标 | 当前或拟用预算 | 处理 |
| --- | --- | --- |
| 普通 pytest 用例 | 30 秒，signal，含 fixture | 沿用；超时失败，不全局放宽 |
| 真实安装用例 | 每项 180 秒 | 沿用独立 install 层；不得改成假安装来省时 |
| pi_live | 每项 180 秒 | 沿用 opt-in；provider 不可用如实记失败／阻塞，不能算成功模型验收 |
| 正式真实任务 | 执行工时默认 7200 秒 | 沿用任务配置；人工等待不计入，具体任务批准预算，不自动追加 |
| 高频测试套件 | ≤60 秒为试行观察目标 | 不含装依赖、覆盖重跑和安全扫描；初期超目标触发审阅，不新增未经校准的硬性能门禁 |
| CI quality / security / commit-policy | 15 / 15 / 5 分钟 | 沿用当前作业时限，调整须记录实际成本依据 |
| 夜间 mutation / install | 180 / 30 分钟 | 沿用；中断与未完成不能当作通过 |
| 偶发失败 | 未处置的关键路径偶发失败 0 | 每次原始失败都留存，重跑不能抹去；先分层和定位再处理 |
| 停止与进程清理 | 在实现规定的截止时间／关闭预算内 | 报告原始延迟和剩余进程；具体 SLA 在真实演练测量后评审 |

对出现过偶发失败的快速子集，修复后在相同环境连续运行 5 次作为短期诊断证据；不是每次推送都重复 5 次，也不把五次通过解释为长期失败率零。对真实模型记录 provider、失败分类、执行时间与可取得用量；尚无实际任务样本时不设置成功率、吞吐或成本硬指标，不恢复已撤销的人工 ROI 测量。

## 11. 报告、例外和交付声明

用报告文件和现有 CLI 记录实现，不引入通用质量数据库／平台。报告保存到现有 reports 根下的单次运行目录或当前 CI artifact；文件名和结构在 Q03 定稿，旧脚本消费路径兼容。CI 普通报告保留当前 7 天；正式任务证据按现有默认保留策略保留，人工清理；保留或备份失败如实记录。

例外固定写：规则、精确位置、理由、审阅者、源码版本、重检条件。源码／契约变动后复核；安全或业务真实缺口不能仅靠例外放行。已有结构例外按其原有字段继续。

完成状态分为：方案已写、配置已接入、负例已验证、真实边界已验证、真实任务已验收。报告缺失／跳过／模型错误／无权限不计成功；旧报告无身份时标“历史参考”。夜间失败不能只靠重新测到绿色关闭，需记录原因和影响。
