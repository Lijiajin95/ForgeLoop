# DSH Web 独立验证环境方案

**拟议，待评审。** 在独立 DSH Web 实例完成 ForgeLoop 候选包的试装、真实模型闭环和性能复测。正式宿主停机、正式配置和业务库均不存在时，验证仍能从候选包与测试材料启动并完成。正式实例的上线核对沿用发布流程。首批覆盖 ForgeLoop 候选包验收，正式需求自动跨宿主送验另行设计。 [产品方案 §10.5](../product/product.md#105-测试环境与模型接入) · [安装后检查](deployment.md#6-安装后检查)

## 1. 环境与输入

每轮在独立测试根下创建新的运行目录，启动专用 DSH Web 进程。复验分配新目录，可以复用同一候选包和版本化测试材料。报告归档在测试根下单独的 `evidence/<run-id>/`，与本轮待清理的目录分开。

| 对象           | 每轮使用的资源                                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 安装包         | 候选包验收显式传入 tarball 路径与 SHA-256。核对摘要后复制到本轮目录，试装和结果绑定同一摘要。                                                            |
| DSH            | 独立的 `DSH_HOME` 和 `DSH_AGENTS_HOME`，从发行版内置的 `web` 模板初始化测试 profile。监听 `127.0.0.1` 的空闲端口，用该进程签发的凭据建立独立浏览器会话。 |
| ForgeLoop      | 本轮生成配置和绝对 `recordsRoot`。注册本轮 Git 仓库为 DSH 工作区，业务会话绑定该工作区。需求、SQLite、任务副本、候选和日志均落在本轮目录内。             |
| Git 与业务数据 | 初始化独立 Git 仓库，使用版本化的合成需求和测试数据。涉及迁移、回退或恢复时，使用固定版本的测试快照与上一已验证包。                                      |
| 模型与外部资源 | 无模型冒烟无需模型凭据。真实模型场景使用本轮指定的测试凭据和路由。运维和部署默认关闭。涉及安装和运行核对时，只登记本轮测试目标。                         |

启动环境只传递 DSH、Node、Git、包管理器和本轮场景所需的变量，DSH 及验证命令从测试目录启动。现有验证子进程会继承宿主环境变量，因此启动器须排除正式数据库、应用 API 与其他资源的连接配置和凭据。有文件或网络副作用的场景，须验证宿主现有沙箱或受控执行器能限制可访问资源。未能建立所需约束时，记为环境未就绪。同一 OS 用户下的目录分离只作为配置与数据隔离的依据。 [子进程执行](../../packages/forgeloop/src/runtime/formal-test.ts) · [产品方案 §8.3](../product/product.md#83-运维职责与简化要求)

## 2. 首条测试需求前的检查

1. **启动前限定路径。** 在启动、安装和清理入口检查解析后的实际路径。配置、DSH home、工作区、记录根和可写输出须位于本轮允许目录。发现越界、路径链接指向外部或配置缺失即拒绝。候选包只作为输入读取。
2. **装载前核对组合配置。** 使用 `--dump-config` 在启动服务前检查配置。由本轮生成的 `FORGELOOP_CONFIG` 提供记录根和基准项目路径，组合后的宿主配置存在 `recordsRoot` 或 `projectPath` 覆盖即拒绝，防止装载时打开其他库。注册工作区前检查项目级配置，确保运维和部署符合本轮约束。 [配置优先级](../../packages/forgeloop/src/config.ts)
3. **启动后核对实际落点。** 核对启动日志的 `records=`、会话绑定的工作区、实际 SQLite 路径、浏览器所连的进程和插件身份。宿主、工作区、安装包或记录库任一不匹配就结束本轮，留下阻断证据。全部通过才提交测试需求。测试需求和报告带同一个运行标识。 [工作区绑定](../../packages/forgeloop/src/runtime/workspace-tenants.ts)

## 3. 验证入口与判定

沿用 `make e2e` 做无模型的装载和 Web 工作区冒烟。用 `make verify-e2e` 安装指定候选包并跑真实模型主路径，Windows 执行同名 `make.cmd` 目标。当前 Web 验收脚本已创建临时宿主、记录根和工作区。启动环境筛选、写入前核对和证据封存纳入首批实施。 [现有验收入口](../../Makefile) · [真实模型脚本](../../scripts/ts/verify-e2e.ts)

| 验收场景       | 可核查结果                                                                                                                                                                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 无生产依赖启动 | 在没有正式宿主、正式数据和正式凭据的现场启动成功。本轮工作区可打开天工看板，日志与 SQLite 实际路径一致。                                                                                                                                                                               |
| 拒绝错配       | 用合成目录和服务模拟记录根越界、链接重定向、profile 覆盖与错宿主。提交前明确阻断，外部目录与服务无写入。                                                                                                                                                                               |
| 同包真实主路径 | 真实 DSH、测试模型和实际工具走完合成需求到受控提交。要求独立验证的场景，须单独核对同一候选的验证和业务终审记录。当前脚本检查提交与任务交付，尚未检查这两份记录。 [现有提交断言](../../scripts/ts/verify-e2e.ts) · [自验分支](../../packages/forgeloop/src/runtime/advance-pipeline.ts) |
| 两轮记录分开   | 两轮并行运行或复验时，进程、端口、会话、工作区、记录库和产物分开。分别查证两边的看板和 SQLite，每条测试需求只存在于受理它的运行目录。                                                                                                                                                  |
| 性能复测       | 在同一台测试机用相同 DSH 版本、合成输入和采样口径比较旧包和候选包。记录回合内页面延迟、CPU 和事件循环，保留两边的包摘要与原始结果。                                                                                                                                                    |

每轮先封存候选摘要、DSH 版本、运行身份、脱敏配置、测试基线、需求编号、用例结果和日志引用，再按本轮进程与目录的身份清理。缺少测试凭据时可完成无模型冒烟，真实模型项标为未验证。合成需求和故障演练单独计量。 [测试计量口径](../product/product.md#102-真实执行与可控替身)

## 4. 首批实施范围

以下清单用于实施评审。先运行通过与拒绝两侧的用例，让拒绝侧在改动前复现目标失败。实现后运行 `make check`，再复跑无模型宿主和真实模型场景。沿用现有命令入口。

| 文件                                                                                                | 用途                                                                             |
| --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `scripts/ts/e2e-environment.ts`（新增）                                                             | 让三条验收脚本共用运行目录、启动环境和路径判定，集中维护隔离规则。               |
| `scripts/ts/e2e.ts`、`scripts/ts/e2e-board.ts`                                                      | 按同一边界准备宿主。看板冒烟核对实际记录库、工作区与进程身份。                   |
| `scripts/ts/verify-e2e.ts`                                                                          | 绑定候选包摘要，在首条需求前校验生效配置和装载结果，核对独立验证证据并封存结果。 |
| `packages/forgeloop/tests/e2e-environment.test.ts`（新增）                                          | 覆盖合法路径、配置冲突、路径越界、错宿主、环境变量筛选和清理拒绝。               |
| `docs/development/deployment.md`、`docs/development/architecture.md`、`docs/verification/status.md` | 同步实际运行步骤、证据位置和验收结果。                                           |
