# ForgeLoop 快速启动验收计划

日期：2026-10-12，Asia/Shanghai。状态：计划，尚未执行。此计划取代原先只读状态页与十五项恢复验证优先的计划。

## 1. 目标

在最多三十小时人工投入内，让 CLI＋LangGraph＋PI 完成一个真实小任务，产出可验收代码 diff、实际测试与审查证据、原始记录。没有必须用满预算的要求，首次闭环通过即可开始使用。

原只读状态页归入 B01。当前不把页面、邮件、附件、自动发布、完整恢复或自升级作为首版完成门槛。

## 2. 最短实现顺序

| 顺序 | 工作 | 停止扩张的条件 |
| --- | --- | --- |
| 1 | 核查工程基线、容器和一组 PI 模型配置；最小 RPC 调用 | 已取得真实事件、稳定结束与可读取会话，立即进入下一步 |
| 2 | 保存文本任务、方案、明确批准与本地记录 | 已能阻止未批准代码执行，不再建设审批后台 |
| 3 | 串联实现、自验证、独立审查、程序正式测试 | 已生成真实候选 diff 与实际测试输出，不加调度和多模型平台 |
| 4 | 加入研发三轮失败／追加记录、时间限额与请求停止 | 一次失败路径真实可观察，中断不盲目重放 |
| 5 | CLI 查询、人工验收与手动备份 | 全部基本记录可回查，交付用户接回 main，不继续做状态页面 |

初始工程由当前开发工具协助建立，bootstrap 与通过 ForgeLoop／PI 完成的改动分开记录。项目和 GitHub 由用户手动建立同步，首次自动任务要有明确可运行工程与测试命令，不要求空仓库通用自动工程化先完成。

先手动跑通 PI、测试和审查的最小路径，再用 LangGraph 串联，避免先搭通用平台后才遇到真实协议问题。具体依赖版本和本地存储在最小技术方案核查。

## 3. 首个真实任务

只选一个小功能或明确缺陷，约定改动范围、用户场景与真实测试命令。当前只关注 ForgeLoop。

候选示例：bootstrap 已有 CLI 状态查询后，由 PI 为其增加 status --json 输出；验收成功任务、失败任务和不存在任务的输出契约与真实记录一致。它是可选真实任务，不在工程基线存在前假称已经实现，也不先开发整个页面。

用户在执行前确认具体目标。大任务人工拆小，不以过小无意义修改或固定示例输出证明交付效率。

## 4. 首版核心检查

所有检查初始为未执行。通过必须来自实际结果：

| ID | 检查 | 证据 |
| --- | --- | --- |
| A01 | 真实代码闭环 | 批准输入、PI 工具与会话、真实 diff、独立审查、实际正式测试及用户验收 |
| A02 | 批准与 main 隔离 | 未批准不改候选代码；PI 无法修改真实 main；最终交付明确基线与改动 |
| A03 | 测试失败与追加 | 正式测试真实失败的路径，加一次而非按用例重复计数；三次后等待，明确追加三个并保留累计记录 |
| A04 | 时间限制与停止 | 超时／请求停止据实记录，已受理与已停止区分；结果不明确时保留现场，不直接再次启动旧动作 |
| A05 | 记录与简单备份 | 原始输入、配置、批准、PI 会话／可取得事件、测试、diff 和报告可回查；完成任务手动备份到真实独立硬盘并核对可读 |

确定性的计数、重复决定与配置规则可用行为测试验证；真实调用、代码修改、工具停止和测试命令必须注明实际集成证据。原生压缩保持启用，若任务没有触发压缩，就标未验证；不人为增加长任务来阻塞第一个小任务交付。

中断识别和禁止重放属于首版检查；自动恢复、无损暂停、零丢失保证和所有故障窗口演练在待实现列表。备份硬盘未挂载时该检查记未通过，不能用普通目录替代，启动开发实验也不能声称已满足备份保证。

## 5. 结果与投入记录

每项记录环境版本、时间、任务／会话／配置／基线身份、实际命令、日志与 diff、通过／失败／未验证、人工投入及 Agent 运行时间。Token／费用只记录实际可取得数据，未知不填零。

三十小时是人工投入上限，Agent 执行时间另计，小任务仍有默认两小时执行限额。到上限汇报通过项、缺口与剩余工作，由用户决定继续投入；不自动加功能或放宽验收。

首版交付：可运行 CLI、一个真实任务的交付记录、基本失败和停止路径证据、运行说明及后置需求。还没有代码，当前文档不构成任何测试已通过的声明。
